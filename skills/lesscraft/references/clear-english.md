# STE-inspired communication

Use only when the user activates ASD-STE100 mode or STE-inspired mode. Apply
it to your own explanations, questions, progress updates, and handoffs across
Build, Clean, Design, and Handoff. Follow the activation scope in `SKILL.md`. Do not
edit project text or change settings merely because this mode is active.

This is an independent, STE-inspired guide, not a complete implementation of
ASD-STE100 or a claim of conformance. The standard includes writing rules and
a controlled vocabulary. A short checklist does not establish compliance.
This mode is not a conformance checker or an ASD-endorsed product.
Do not bundle its manual, dictionary, or copied examples. If formal conformance
is requested, explain this limit and require the applicable authorized standard
and appropriate review rather than promising certification.

- Put the result or required action first.
- Name the actor when responsibility could be unclear.
- Prefer concrete verbs and familiar words. Keep a precise technical term
  when replacing it would lose meaning.
- Use one term consistently for one concept. Define a necessary unfamiliar
  term near its first use.
- Keep each sentence focused on one main idea. Split dense instructions
  into a short sequence when order matters.
- Use short, complete sentences. Put one action in each procedural step.
- Avoid idioms and figurative phrases that make technical meaning unclear.
- Put a condition before the action it controls when that prevents mistakes.
- Distinguish requirements from options and observations from assumptions.
- State a useful limit explicitly: what was checked, where it applies, or
  which result is still unknown.
- Preserve code, commands, exact identifiers, quotations, facts, and required
  terminology. Keep uncertainty, conditions, and negatives intact. Do not
  rewrite code or a contract to fit a prose preference.

Example:

Less clear: “Validation of the configuration should be undertaken prior to
the initiation of deployment.”

Clearer: “Check the configuration before you deploy.”

Prefer clarity over a mechanical word limit or a forced tone. Follow the
user's requested language and format.

Scope references: [ASD-STE100 overview](https://www.asd-ste100.org/about_STE.html)
and [checking limitations](https://www.asd-ste100.org/STEsoftware.html).
